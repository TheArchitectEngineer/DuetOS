# DuetOS docs and wiki maintenance

`wiki/` is the single canonical documentation home. This skill is the mechanic's manual for
it: where things live, which of the two auto-generation systems owns which page, which
commands regenerate and check what, how to write or amend a page, and the known rot spots
you must fix on contact (per the project's Fix-Anything-You-Surface rule).

**Not this skill:** the *policy* of when docs must change as part of a code slice
(Definition of Done, roadmap graduation triggers) lives in `duetos-change-control`. CI
wiring lives in `duetos-ci-and-release`. This skill assumes you already know a doc edit is
required and tells you how to make it correctly.

## The two AUTO dialects — never confuse them

Two auto-generated-section systems coexist in `wiki/`. They have different marker shapes,
different owners, and different page sets. Editing inside either kind of block by hand is
wasted work: the next regeneration overwrites the region completely.

| | LEGACY (paired markers) | NEW (START/END + kwargs) |
|---|---|---|
| Marker shape | `<!-- AUTO:name -->` … `<!-- /AUTO:name -->` | `<!-- AUTO:<id> [k=v ...] START -->` … `<!-- AUTO:<id> END -->` |
| Owner tool | `docs/sync-wiki.sh` (bash, awk-based) | `tools/build/gen-wiki-auto.py` (Python 3) |
| Section IDs | `syscall_list`, `syscall_args`, `cap_list`, `driver_list`, `dll_list`, `stats` | `thunks-by-dll`, `journal-detectors`, `shell-commands` (registry: `_GENERATORS` dict at bottom of the script) |
| Pages | `wiki/specifications/Syscall-ABI.md` (syscall_list, syscall_args), `wiki/security/Capabilities.md` (cap_list), `wiki/drivers/Driver-Overview.md` (driver_list), `wiki/subsystems/Win32-DLLs.md` (dll_list), `wiki/Home.md` (stats) | `wiki/reference/Win32-Surface-Status.md` (18× `thunks-by-dll DLL=<name>.dll`), `wiki/security/Fix-Journal.md` (journal-detectors), `wiki/reference/Shell-Commands.md` (shell-commands) |
| Check mode | `docs/sync-wiki.sh check` (dry-run report) | `python3 tools/build/gen-wiki-auto.py --check` (exit 1 on drift — the CI-style gate) |
| Arguments | none | `key=value` pairs on the START marker only (no spaces in values); END marker takes none |
| Unknown IDs | silently ignored (marker must pre-exist; sync creates some blocks if missing) | left untouched by design, so future generators can be referenced before they exist |
| Generated banner | none | first line is `<!-- generated by tools/build/gen-wiki-auto.py — do not edit by hand -->` |

Shared contract (spec: `wiki/tooling/Wiki-Auto-Sections.md`): **the region between the
markers is fully generator-owned.** Nothing hand-written survives inside. Hand-written
prose goes outside the block; a generator that wants to interleave prose must embed it
itself. This keeps `--check` deterministic.

**Merge-conflict rule** (from `CLAUDE.md`): in any rebase/merge conflict inside an AUTO
block, take upstream, then regenerate. Never hand-resolve generated content.

## Command reference

All commands run from the repo root, in bash (Git Bash or WSL — these are bash scripts).

| Command | What it does | Exit behaviour |
|---------|--------------|----------------|
| `bash docs/sync-wiki.sh` (or `sync`) | Full legacy sync: scans kernel/drivers/subsystems/userland, rewrites the 6 legacy AUTO sections, refreshes Home.md stats, flags wiki pages referencing files/classes that no longer exist | writes in place |
| `bash docs/sync-wiki.sh check` | Dry-run: report what is out of date | report only |
| `bash docs/sync-wiki.sh status` | Show sync status | report only |
| `python3 tools/build/gen-wiki-auto.py` | Regenerate every new-dialect AUTO block in `wiki/**/*.md` | writes in place |
| `python3 tools/build/gen-wiki-auto.py --check` | Check-only gate: exit 1 if any block on disk differs from regenerated | exit 1 on drift |
| `python3 tools/build/gen-wiki-auto.py wiki/reference/Win32-Surface-Status.md` | Limit regeneration to specific files | writes in place |
| `bash tools/check-wiki-nav.sh` | Bidirectional sidebar check: every wiki page listed in `_Sidebar.md` and vice versa | exit 1 on issues |
| `bash tools/check-wiki-quality.sh` | Stale hardcoded metrics in top-level pages, `_Template.md` presence, missing Audience/Execution-context/Maturity frontmatter blocks | exit 1 on issues; `--warn-only` to downgrade |
| `bash tools/dev/check-local.sh` [inside WSL, scratch tree — see `duetos-build-and-env`] | Umbrella local gate; its wiki step runs nav + quality (skip with `--no-wiki`). It does NOT run sync-wiki.sh or gen-wiki-auto.py — run those yourself | per-step |

**CI status (as of 2026-08-13):** none of these are wired into GitHub CI —
`.github/workflows/build.yml` paths-ignores `docs/` and `wiki/`. Wiki hygiene is local
discipline only. `gen-wiki-auto.py --check` is *designed* as a CI gate but is currently
`open` (unwired). Do not claim "CI will catch it".

## Runbook: landing a slice — the docs edits

Run this after the code is done, before commit. (WHEN each step is mandatory is
`duetos-change-control`'s contract; this is the HOW.)

1. **Regenerate both AUTO dialects** so inventories match the new code:

   ```bash
   bash docs/sync-wiki.sh sync
   python3 tools/build/gen-wiki-auto.py
   ```

   Diff the result (`git diff --stat wiki/`) — regenerated blocks changing is expected;
   hand-written prose changing is not.

2. **Roadmap graduation** — if the slice lands an item from `wiki/reference/Roadmap.md`:
   delete its entire section from Roadmap.md **in the same commit**. The page's own "How
   to graduate an item" section (~line 1600) is the authority:
   - Delete the entry from Roadmap.md.
   - Add a `Design-Decisions.md` entry (one per non-trivial commit).
   - Update `wiki/getting-started/History.md` if a project-level milestone moved.
   - Update the owning subsystem page's "Known Limits" section.

   A "shipped/landed/DONE" paragraph left in Roadmap.md is cleanup debt — the convention
   is deletion, with at most a one-line index pointer to a slice plan on a subsystem page.
   (Exception: the "Program backlog — ordered" section at ~line 1615 strikes items with
   `~~...~~ LANDED` because it is a running order, not a work-item list.)

3. **Flip status rows** — if the slice changed a Win32 surface from STUB→REAL etc., the
   row lives inside an AUTO block in `wiki/reference/Win32-Surface-Status.md`, so fix the
   *source of truth the generator reads* (the thunk tables/markers in code), then
   regenerate. Do not hand-edit the table.

4. **Update the owning wiki page** (`wiki/<area>/...`) — hand-written prose: new
   behaviour, new known limits, removed limitations.

5. **Verify**:

   ```bash
   python3 tools/build/gen-wiki-auto.py --check
   bash docs/sync-wiki.sh check
   bash tools/check-wiki-nav.sh
   bash tools/check-wiki-quality.sh
   ```

   Every reported issue is a fix target — including pre-existing ones you did not cause.

## Page authoring: new page vs amend

Write a **new** page when: a new subsystem lands and is wired into the boot path; a new
driver class appears under `kernel/drivers/`; a new userland Win32 DLL appears under
`userland/libs/`; a new spec (ABI, file format, protocol) is committed; or a topic
accumulates enough cross-references that one canonical page beats inlining everywhere.

**Amend** instead when: the topic is a one-paragraph addendum to an existing page; it is a
transient to-do item (→ a Roadmap.md row); or it is a slice postmortem already captured in the
subsystem page or commit message.

New-page checklist:

1. Copy `wiki/_Template.md`. Keep the opening blockquote triple — `check-wiki-quality.sh`
   flags pages missing it:

   ```markdown
   > **Audience:** <Kernel hackers | Driver authors | App / PE devs | QA | Mixed>
   >
   > **Execution context:** <Kernel | Userland | Both | IRQ-safe / sleep-safe / process>
   >
   > **Maturity:** <v0 (just lands) | active | stable | deprecated>
   ```

2. Name it `Title-Case-With-Hyphens.md`, place it under the matching area directory
   (`wiki/kernel/`, `wiki/drivers/`, `wiki/security/`, ...).
3. Add a link line to the matching `###` section of `wiki/_Sidebar.md` — then run
   `bash tools/check-wiki-nav.sh` (it checks both directions: file without sidebar entry
   AND sidebar entry without file).
4. House style: template section order (Overview → When to Use → Threading & Locking →
   Capability Surface → Key APIs → Performance → Known Limits/GAPs/STUBs →
   Troubleshooting → Related Pages); exact source paths in backticks; a "Known Limits"
   section mirroring any `// STUB:` / `// GAP:` markers in the code it documents.
5. Never hand-count inventories. STUB/GAP totals come from
   `git grep -nE "// (STUB|GAP):"` and are published by `AUTO:stats` in `Home.md`
   (99 STUB / 280 GAP as of the 2026-08-01 sync). Hardcoding a count in prose creates a
   stale metric `check-wiki-quality.sh` exists to catch.

## Design-Decisions.md entry format

`wiki/reference/Design-Decisions.md` is **append-only at the bottom**. ~300 entries, two
ID schemes coexist (do not "fix" this): early numbered entries (`001`–`126`) and dated
headings (`## 2026-MM-DD - <title>`, some with `### DD#NNN — <title> (date)` sub-IDs).
A third numbered run (`## 055`–`## 058`, numbers reused) sits at the tail — appended by
the 2026-08-01 fleet wave. Superseded entries get an inline "superseded by ..." note —
never deleted.

Per-entry skeleton (match the neighbours at the bottom of the file):

```markdown
## 2026-08-13 - <one-line decision title>

- **Scope & commit:** <files/subsystem touched; commit ref if known>
- **Decision:** <what was decided>
- **Why:** <the forcing constraint>
- **What it rules out / defers:** <alternatives now off the table>
- **Revisit when:** <the concrete trigger that reopens this>
- **Related roadmap tracks:** <Roadmap.md sections or "none">
```

Write an entry when a change rules out an alternative a future slice could otherwise pick.
Skip it for pure refactors that keep all options open.

## Hazards

- **NUL bytes silently disable the stale-reference check.** Historical incident
  (`HANDOFF.md` ~line 105): `Design-Decisions.md` once held 3136 NUL bytes from a
  concurrent append; `grep` classified it as binary and `sync-wiki.sh`'s stale-reference
  scan printed `Binary file ... matches` instead of working — masking a real stale path.
  If sync-wiki reports nothing for a huge file, verify first:

  ```bash
  file wiki/reference/Design-Decisions.md   # must say "text", not "data"
  grep -c . wiki/reference/Design-Decisions.md
  ```

- **Run `gen-wiki-auto.py` from bash, not a Windows shell.** It once corrupted the wiki
  when run on Windows (backslash paths and CRLF written into generated blocks —
  `HANDOFF.md` ~line 102). The script now pins LF (`newline="\n"`) and POSIX paths
  (`as_posix()`), so this is fixed at source — but the repo is LF-only, so keep doc
  tooling in Git Bash/WSL and check `git diff` for `^M` if a whole block shows as changed.
- **`sync-wiki.sh check` still mutates nothing but `sync` writes 6 sections at once** —
  run `check` first in a dirty tree so regeneration noise doesn't mix with your edits.
- **Home.md "Wiki pages" stat (135) ≠ `find wiki -name '*.md' | wc -l` (137).** The stats
  counter excludes some files (e.g. `_Sidebar.md`/`_Template.md`); not a bug, don't
  "fix" the number by hand — it lives inside `AUTO:stats`.
